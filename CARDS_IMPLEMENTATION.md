# Mayhemate — спецификация реализации эффектов карт

Документ для кодинг-модели. Основа — `GAME_LOGIC.md` и код `src/game/*`. Каталог карт: `cards.json` (массив объектов; если загрузчик ждёт `{ "cards": [...] }`, оберните).

Цель: сделать `effects` исполняемыми через небольшой интерпретатор (`src/game/effects.ts`) и добавить недостающее состояние (кладбище, ловушки, статусы).

---

## 0. Принципы

1. Карта по-прежнему разыгрывается на **клетку** (`target: "cell"`). Карты без привязки к фигуре (добор, темп) принимают **любую** клетку, она игнорируется.
2. Все эффекты — **детерминированные** при одинаковом состоянии. Любой рандом только через серверный/хостовый RNG, состояние которого хранится в `GameState` (см. §9).
3. Весь урон проходит через одну функцию `dealDamage`, вся смерть — через `removePiece`. Никаких прямых `piece.hp -= x` в эффектах.
4. Валидация карты (`requires`) происходит **до** списания темпа. Невалидная цель → `invalid-target`, карта остаётся в руке, темп не тратится.
5. Новые поля обязательно сериализуются в `toState` / `fromState`.

## 1. Изменения модели данных

### 1.1 Piece
```ts
interface Piece {
  id; type; col; row; color; hp; atk;   // как раньше
  maxHp: number;            // NEW. Инициализируется базовым HP типа. Лечение ограничено maxHp.
  tempAtk: number;          // NEW. Временный бонус атаки, по умолчанию 0. Эффективная атака = max(0, atk + tempAtk).
  status: {                 // NEW. Все поля опциональны.
    shield?:   { charges: number };
    frozen?:   { turns: number };
    poison?:   { turns: number; damage: number };
    bomb?:     { turns: number; damage: number; area: string; killHolder: boolean; by: Color };
    lifelink?: true;
    thorns?:   { damage: number };
    expire?:   { turns: number };
  };
}
```
Для существующих фигур при создании/загрузке старого сейва: `maxHp = hp`, `tempAtk = 0`, `status = {}`.

### 1.2 GameState (добавить)
```ts
graveyard: { white: DeadPiece[]; black: DeadPiece[] };   // DeadPiece = { type, color, id }, последний погибший — в конце массива
traps: Trap[];                                           // Trap = { id, col, row, owner: Color, kind: 'mine'|'frost_trap', params, revealedTo: Color[] }
tempoMod: { white: number; black: number };              // модификатор темпа на СЛЕДУЮЩИЙ ход этого цвета, по умолчанию 0
rngState: number;                                        // состояние RNG для эффектов (см. §9)
nextPieceId: number;                                     // счётчик для призванных фигур, id вида `${color}_s${n}`
```
`graveyard` — **по цвету погибшей фигуры**. «Из своего кладбища» = `graveyard[caster]`, «из вражеского» = `graveyard[opponent]`.

## 2. Формат карты

```jsonc
{
  "id": "...", "name": "...", "text": "...", "cost": 2, "copies": 2, "art": "", "target": "cell",
  "requires": { ... },   // NEW: валидация цели. Каталог-нормализатор должен СОХРАНЯТЬ это поле.
  "effects":  [ ... ]    // NEW: исполняется по порядку
}
```

### 2.1 `requires` (все указанные условия — через И)

| Поле | Значение | Смысл |
|---|---|---|
| `cell` | `"any"` \| `"empty"` \| `"piece"` | на клетке нет ограничений / нет фигуры / есть фигура |
| `owner` | `"ally"` \| `"enemy"` \| `"any"` | владелец фигуры относительно играющего (только при `cell:"piece"`) |
| `types` | `["pawn",...]` | фигура одного из типов |
| `notTypes` | `["king"]` | фигура не этих типов. Для карт с `graveyard` — тип воскрешаемой фигуры (см. ниже) |
| `hpMax` / `hpMin` | число | `piece.hp <= hpMax` / `piece.hp >= hpMin` |
| `acted` | `true` | `piece.id` уже в `turnMove` |
| `noTrap` | `true` | на клетке нет ловушки (любой стороны, без раскрытия информации — если ловушка есть, отвечать `invalid-target` одинаково для обеих сторон) |
| `zone` | `"own_home2"` \| `"own_half"` \| `"enemy_half"` | регион клетки (определения в §2.4) |
| `graveyard` | `"own"` \| `"enemy"` | соответствующее кладбище должно содержать хотя бы одну фигуру, подходящую под `notTypes` |

Если `requires` отсутствует — считать `{ "cell": "any" }`.

### 2.2 Селекторы области: `area` и `filter`

Каждая операция по умолчанию действует на **фигуру на выбранной клетке** (`area: "cell"`). Для массовых эффектов указывается `area` + `filter`.

| `area` | Клетки |
|---|---|
| `cell` | только центр (по умолчанию) |
| `adjacent8` | 8 соседних, **без центра** |
| `square3` | 3×3 с центром |
| `square5` | 5×5 с центром |
| `cross` | центр + 4 ортогональных соседа |
| `row` | весь ряд центра |
| `col` | вся колонка центра |
| `board` | вся доска |

`filter`: `{ "owner": "ally"|"enemy"|"any", "types": [...], "notTypes": [...] }`. Значение по умолчанию для `owner` — `"any"`. Если `area:"cell"` и фильтра нет — действует на любую фигуру на клетке (валидность уже проверена `requires`).

Целями операции становятся фигуры, **собранные до начала** применения операции (снимок), порядок — по возрастанию `row`, затем `col` (детерминизм).

### 2.3 Вложенные цепочки
- `then: [ops]` — выполняется после операции, **если она затронула хотя бы одну цель / сработала**.
- `onKill: [ops]` (только у `damage`) — выполняется, если хотя бы одна цель погибла от этой операции.
- Вложенные операции без `area` действуют на **исходную выбранную клетку** (если там уже нет фигуры — фигурные операции просто ничего не делают). Операции «на себя» (`draw`, `tempo`, …) не зависят от клетки.

### 2.4 Регионы (`zone`) — для белых / чёрных
- `own_home2`: белые rows 6–7, чёрные rows 0–1.
- `own_half`: белые rows 4–7, чёрные rows 0–3.
- `enemy_half`: белые → rows 0–3, чёрные → rows 4–7.

## 3. Порядок разрешения `PLAY_CARD`

1. Проверки как сейчас: очередь хода, карта в руке, целочисленная цель в доске, `cost <= tempo`.
2. `validateRequires(card, color, col, row)` → иначе `invalid-target`.
3. Списать темп, карту из руки в сброс, событие `card` (как сейчас).
4. Для каждого элемента `effects` по порядку: `applyEffect(op, ctx)`.
5. После **каждой** операции обработать смерти (они уже обрабатываются в `removePiece`, см. §7) и срабатывание ловушек, если фигура переместилась.
6. Фигурные операции, нашедшие 0 целей, молча завершаются (не ошибка): состояние могло измениться из-за предыдущих операций.

`ctx = { state, caster: Color, col, row, rng }`.

## 4. Каталог операций

### Урон / лечение / усиление

| op | Параметры | Поведение |
|---|---|---|
| `damage` | `amount`, `pierce?`, `onKill?`, `then?` | `dealDamage(target, amount, { pierce })` для каждой цели |
| `heal` | `amount` | `hp = min(maxHp, hp + amount)` |
| `buff` | `hp?`, `atk?`, `duration` | `duration:"permanent"`: `hp` увеличивает **и** `hp`, **и** `maxHp`; `atk` увеличивает `atk` (итог не ниже 0). `duration:"turn"`: `atk` добавляется в `tempAtk` (сбрасывается в конце хода, §6). `hp` с `"turn"` не используется |
| `kill` | `exile?`, `then?` | `removePiece(target, { exile })`. Без `exile` фигура попадает на кладбище. Урон/щит игнорируются |

### Статусы

| op | Параметры | Поведение |
|---|---|---|
| `set_status` | `status` + параметры статуса | Записывает/обновляет `piece.status[status]`. Повторное наложение: `turns` берётся как max(старое, новое), `charges` суммируются, остальные параметры перезаписываются. Подробности статусов — §5 |

### Перемещение / состав фигур

| op | Параметры | Поведение |
|---|---|---|
| `push` | `distance`, `from:"center"`, `collisionDamage`, `area`, `filter` | Каждую цель сдвинуть на `distance` клеток по направлению «от центра» (знак `dc`, `dr` разности цели и центра, диагональ сохраняется). Если следующая клетка вне доски или занята фигурой → цель остаётся на месте и получает `collisionDamage` (через `dealDamage`, без `pierce`). Обрабатывать цели в порядке «дальше от центра первыми», но так как все стоят на `adjacent8`, достаточно порядка по §2.2. После перемещения — проверка ловушек |
| `teleport` | `to:{ random_empty:true, radius:N }` | Цель переносится на случайную пустую клетку в квадрате радиуса `N` (Чебышёв) от **её текущей** позиции. Если пустых нет — ничего. Проверка ловушек после |
| `swap` | `with:"own_king"` | Меняет местами цель и короля **caster**-а. Если короля нет — ничего. Проверка ловушек для обеих фигур |
| `summon` | `type`, `hp?`, `atk?`, `exhausted?`, `status?:[{status,...}]` | Создаёт фигуру цвета caster на выбранной (пустой) клетке. Базовые `hp/atk` из таблицы типов, если не переопределены; `maxHp = hp`. `exhausted:true` → id сразу в `turnMove` (не может действовать в этот ход). `status` — список статусов для установки. Проверка ловушек после |
| `resurrect` | `from:"own"|"enemy"`, `notTypes`, `hp:"half"|N`, `asOwner?:"self"`, `exhausted?` | Берёт **последнюю** подходящую запись кладбища (`graveyard[...]`, искать с конца, пропуская `notTypes`), удаляет её оттуда, создаёт фигуру на выбранной пустой клетке. `hp:"half"` = `ceil(baseHp/2)`; число = абсолютное. `maxHp = baseHp` типа. Цвет — цвет caster, если `asOwner:"self"` или `from:"own"`. Новый `id` через `nextPieceId` |
| `transform` | `type` | Меняет `type` цели, ставит `hp = maxHp = baseHp(type)`, `atk = baseAtk(type)`. Статусы сохраняются. `tempAtk = 0`. Пешка → конь/ферзь используют обычные правила движения нового типа |
| `set_owner` | `to:"caster"`, `exhausted?` | Меняет `color` цели на цвет caster. `exhausted:true` → добавить id в `turnMove`. Фигура перестаёт быть союзником прежнего владельца, статусы остаются |
| `grant_action` | `resetMoveFlag?` | Удаляет `piece.id` из `turnMove`. Если `resetMoveFlag:true` — `movedThisTurn = false`. Темп не возвращается |

### Ловушки

| op | Параметры | Поведение |
|---|---|---|
| `place_trap` | `trap`, параметры ловушки; либо `random:{count,zone}` | Без `random`: ловушка на выбранной пустой клетке, `owner = caster`, `revealedTo = [caster]`. С `random`: выбрать `count` **различных** пустых клеток зоны без ловушек (RNG, §9); если клеток меньше — столько, сколько есть |
| `destroy_trap` | `owner:"enemy"|"ally"|"any"`, `then?` | Удаляет ловушки на выбранной клетке указанного владельца. `then` выполняется, только если что-то удалено. Игроку не сообщается, была ли ловушка, кроме как через эффект `then` |
| `reveal_traps` | `area` | Для всех вражеских ловушек в области добавляет caster в `revealedTo` |

### Карты и темп

| op | Параметры | Поведение |
|---|---|---|
| `draw` | `count`, `who:"self"` | Добор `count` карт с учётом `MAX_HAND_SIZE` и пустой колоды (лишние не берутся) |
| `discard_random` | `count`, `who:"self"|"opponent"`, `then?` | Случайные карты из руки уходят в сброс. `then` выполняется, только если сброшена хотя бы одна карта |
| `steal_card` | `count` | Случайная карта из руки противника переходит в руку caster. Если рука caster полна — карта уходит в сброс. Если у противника рука пуста — ничего |
| `tempo` | `amount`, `who:"self"` | Прибавляет текущему темпу `amount`, но не выше **7** (`TEMPO_HARD_CAP`) |
| `tempo_next_turn` | `amount`, `who:"opponent"`, `min` | `state.tempoMod[opponent] += amount`. Применяется в начале хода (см. §6), итоговый темп не ниже `min` |

## 5. Статусы

| Статус | Параметры | Когда действует |
|---|---|---|
| `shield` | `charges` | В `dealDamage`: если `charges > 0` и не `pierce` → урон = 0, `charges--`, событие `shield`. Статус удаляется при `charges = 0` |
| `frozen` | `turns` | Фигура не может `MOVE` (ни ходить, ни атаковать): ошибка `frozen`. В конце хода **её владельца** `turns--`, при 0 статус удаляется. Заморозка не мешает быть целью карт |
| `poison` | `turns`, `damage` | В начале хода владельца фигуры: `dealDamage(piece, damage, { pierce:true })`, `turns--`, при 0 снять |
| `bomb` | `turns`, `damage`, `area`, `killHolder`, `by` | В начале хода цвета `by`: `turns--`; при 0 — урон `damage` всем фигурам в `area` вокруг носителя (оба цвета, `filter owner:any`), затем если `killHolder` — `removePiece(holder)`. Записывать `by = caster` при установке |
| `lifelink` | — | Если эта фигура **атакует** (`MOVE` в клетку врага) и нанесла `d > 0` урона (после щита): `heal(attacker, d)` (до `maxHp`). Урон картами — без эффекта |
| `thorns` | `damage` | Если эту фигуру **атаковали** (`MOVE` врага), после получения урона (даже если она погибла/щит поглотил — нет, только если фигура ещё жива или урон > 0): атакующий получает `dealDamage(attacker, damage, { pierce:false })`. Упрощённое правило: срабатывает на каждую атаку, независимо от щита и смерти цели; если атакующий погибает — он удаляется до перемещения на клетку жертвы |
| `expire` | `turns` | В начале хода владельца: `turns--`; при 0 — `removePiece(piece, { exile:true })` (на кладбище не попадает) |

## 6. Ход: изменения в `END_TURN`

Порядок:
1. Сбросить `tempAtk = 0` у **всех** фигур.
2. Уменьшить `frozen.turns` у фигур **того цвета, чей ход закончился**; снять при 0.
3. Очистить `turnMove`, `movedThisTurn = false` (как сейчас).
4. Сменить `turn`, обновить `turnCount` и `maxTempo` (как сейчас).
5. `tempo[turn] = clamp(maxTempo + tempoMod[turn], min 1, max 5)` — если `tempoMod[turn] != 0`, то потом обнулить `tempoMod[turn]`. Минимум 1 — всегда, а карта `jam` дополнительно не опускает ниже своего `min`.
6. Добор карты (как сейчас).
7. Тики статусов для нового `turn`:
   - `poison`, `expire` — у фигур цвета `turn`;
   - `bomb` — у любых фигур с `bomb.by === turn`.
   Порядок: `poison` → `bomb` → `expire`. Смерти обрабатываются сразу.

## 7. Центральные функции (обязательно)

```ts
dealDamage(target, amount, opts: { pierce?: boolean; attacker?: Piece })
```
1. `amount <= 0` → выход.
2. Если есть `shield` и нет `pierce` → поглотить, событие `shield`, выход (кроме обработки `thorns`/`lifelink`, см. §5).
3. `target.hp -= amount`; событие `damage`.
4. Если `hp <= 0` → `removePiece(target)`.

```ts
removePiece(piece, opts: { exile?: boolean })
```
1. Убрать с доски.
2. Если не `exile` — `graveyard[piece.color].push({ type, color, id })`.
3. Событие `kill`/`death`.

**Атака в `MOVE`** должна использовать `dealDamage(target, attacker.effAtk, { attacker })`; остальная логика (перемещение после убийства, один ход на фигуру, `movedThisTurn`) не меняется. `effAtk = max(0, atk + tempAtk)`.

**Блокировка заморозки** в `MOVE`: если у фигуры `status.frozen` → ошибка `frozen`.

**Ловушки.** Функция `checkTraps(piece)` вызывается каждый раз, когда фигура оказалась на клетке: обычное перемещение, перемещение после убийства при атаке, `push`, `teleport`, `swap`, `summon`, `resurrect`. Если на клетке есть ловушка с `owner !== piece.color`:
- `mine`: `dealDamage(piece, trap.damage)`;
- `frost_trap`: `set_status frozen turns = trap.turns`;
- ловушка удаляется (одноразовая); событие `trap` (видимо обоим игрокам).
Ловушка своего цвета не срабатывает и остаётся. Если на клетке несколько ловушек — срабатывают по порядку создания.

## 8. События для UI

Добавить (в дополнение к `attack`, `kill`, `move`, `card`): `damage {id, amount}`, `heal`, `shield`, `status {id, status}`, `summon`, `resurrect`, `transform`, `trap_placed {col,row}` (только владельцу!), `trap {col,row,kind}` (обоим), `draw`, `discard`, `steal`, `tempo`.

Рендер:
- HP/ATK фигуры показывать с `maxHp` и `tempAtk` (например, зелёным при бонусе).
- Иконки статусов над фигурой: щит, лёд, яд, бомба.
- Ловушки рисуются **только** для владельца и для тех, кто в `revealedTo`. Локальный режим (hot-seat): показывать ловушки цвета `turn`; не раскрывать чужие при смене хода.

## 9. Сеть и RNG

- Рандом эффектов (`teleport`, `place_trap.random`, `discard_random`, `steal_card`) — через общий детерминированный RNG (mulberry32 и т. п.) с состоянием в `state.rngState`. Вызывать **только в хосте** (или в локальной игре). Гость получает уже применённое состояние.
- Хост при отправке состояния гостю **вырезает** из `traps` те, где `owner !== guestColor` и `guestColor ∉ revealedTo`. И так же скрывает руку/колоду противника (как сейчас).
- Событие `trap_placed` отправлять только владельцу.
- Валидация `requires` — на хосте. Для `noTrap` при отказе возвращать то же `invalid-target`.

## 10. Рекомендуемая структура кода

```
src/game/effects.ts      // applyEffect(op, ctx), selectTargets(area, filter, ctx), validateRequires
src/game/statuses.ts     // tickStart(state, color), tickEnd(state, color)
src/game/traps.ts        // placeTrap, checkTraps, revealTraps
src/game/damage.ts       // dealDamage, removePiece
```
Диспетчер: `const handlers: Record<string, (op, ctx) => boolean /* затронуто что-то? */>`. Неизвестный `op` → предупреждение в консоль, пропуск (не падение).

## 11. Минимальные тест-кейсы

1. `spark` по фигуре с `shield` — урон 0, щит снят.
2. `lightning` убивает пешку (hp 2) → вернулся 1 темп (итоговая стоимость 1).
3. `fireball` в центре скопления: 2 урона центру, 1 соседям обоих цветов.
4. `mine`: вражеская фигура ходит на клетку → 3 урона, ловушка удалена; своя фигура ходит — ничего.
5. Атака, убившая цель на клетке с миной, — атакующий перемещается и получает урон от мины.
6. `resurrect` при пустом кладбище/только король → `invalid-target`, темп не списан.
7. `necromancy`: фигура врага появляется цвета caster, не может действовать в этот ход.
8. `freeze` в ход белых: чёрные не могут ходить фигурой весь свой следующий ход; в конце хода статус снят.
9. `time_bomb`: взрыв ровно в начале 2-го хода caster-а; носитель умер, соседи получили урон.
10. `second_wind` на фигуру, которая ходила: можно снова ходить, и `movedThisTurn` сброшен.
11. `adrenaline` с пустой рукой после розыгрыша → темп не растёт (`then` не выполнен).
12. `jam`: у противника темп в следующем ходу `max(1, maxTempo - 1)`, затем `tempoMod` обнулён.
13. Сохранение/загрузка (`toState`/`fromState`) с активными ловушками, статусами, кладбищем.
14. Гость не видит вражеские ловушки в присланном состоянии; `scout` показывает ловушки в 5×5.

## 12. Важное замечание о правилах игры

В коде **нет условия победы**. Карты `execute`, `necromancy`, `mind_control`, `swap_king` и `resurrect` написаны с расчётом, что короля нельзя убить/забрать картой-эффектом «мгновенно». Рекомендуется добавить: **игрок проигрывает, когда его король удалён с доски** (проверка в `removePiece` → событие `game_over`). Если это не будет добавлено, баланс карт всё равно сохраняется, но у партии не будет финала.
